# Миграции и подключения backend

Локальный API (`APP_ENV=local`) перед стартом применяет миграции отдельным пулом до двух соединений (Flyway использует отдельное соединение для PostgreSQL lock), затем открывает рабочий пул и проверяет схему. Если заданы оба `MIGRATION_DATABASE_USER` и `MIGRATION_DATABASE_PASSWORD`, миграционный пул использует их. Для старой локальной `.env` допустим fallback на `DATABASE_USER`/`DATABASE_PASSWORD`. Рабочий пул не использует миграционные credentials. При отсутствии `APP_ENV` backend выбирает production и не применяет миграции при запуске API.

В production API **не выполняет DDL**. Перед запуском процесса с `APP_ENV=production` отдельно выполняют `./gradlew runMigrations` (Windows: `./gradlew.bat runMigrations`) с `DATABASE_URL`, `MIGRATION_DATABASE_USER` и `MIGRATION_DATABASE_PASSWORD`. Этот запуск не требует JWT secret, использует свой пул и увеличенный socket timeout для DDL. После успешного завершения API стартует с `DATABASE_USER`/`DATABASE_PASSWORD` прикладной роли и проверяет историю Flyway; при невыполненной или неверной миграции не принимает трафик. Прикладной роли нужны SELECT к `flyway_schema_history` и права DML к рабочим таблицам, но не DDL. Существующий локальный `.env` не переносить на production.

`DATABASE_MAX_POOL_SIZE`, `DATABASE_CONNECTION_TIMEOUT_MS`, `DATABASE_STATEMENT_TIMEOUT_MS` и `DATABASE_LOCK_TIMEOUT_MS` ограничивают рабочий пул и транзакции. Значение lock timeout должно быть меньше statement timeout. При планировании нескольких процессов и worker суммарное число соединений держат в пределах бюджета PostgreSQL. `poolSnapshot()` даёт active/idle/waiting/total для будущих метрик; чтение snapshot не заменяет измерение p95. Миграционный пул не наследует короткий runtime socket timeout.

`withJdbcTransaction` выполняет write-транзакцию на IO dispatcher. `withReadOnlyJdbcTransaction` даёт короткий согласованный снимок для нескольких запросов. `withRetryingJdbcTransaction` повторяет всю транзакцию только при deadlock/serialization SQLSTATE; вызывающий код обязан держать внешние эффекты вне повторяемого блока. Advisory key `pointCreation` и ключи адресатов централизованы в `AdvisoryLockKeys`; все использующие их сервисы должны соблюдать один порядок захвата.
