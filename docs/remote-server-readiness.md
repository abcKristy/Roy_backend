# Переезд backend на удалённый сервер

Это накопительный список для будущего развёртывания «Роя». Сейчас backend разрабатывается локально. Отмечайте пункт выполненным только после проверки на выбранном сервере; при каждой новой задаче добавляйте сюда обнаруженные требования с указанием причины и способа проверки. Не записывайте пароли, токены, персональные данные, адреса частной инфраструктуры и содержимое `.env`.

## Решения перед арендой

- [ ] Выбрать сервер и регион размещения с учётом первичной записи и хранения данных граждан РФ, фактической стоимости всего внешнего контура до 5 000 ₽/мес и условий провайдера. Зафиксировать CPU, RAM, диск, ОС, сеть и резервное копирование.
- [ ] Проверить нагрузку Argon2id на выбранной VM: одиночные и одновременные входы/регистрации, задержку, потребление памяти и безопасное число параллельных операций. При необходимости изменить параметры без потери проверки старых encoded hashes. Локальные измерения описаны в [password-hashing.md](password-hashing.md).
- [ ] Определить публичный HTTPS-домен backend и постоянный адрес политики. Проверить доступность с Android и iOS устройств, а не только с компьютера разработчика.
- [ ] Утвердить оператора персональных данных, контакты, фактические сроки/место хранения, получателей данных и окончательный текст политики по действующей на дату выпуска редакции закона. Опубликовать действующую версию; черновую версию и локальные тестовые согласия не переносить в публичный контур.

## Подготовка сервера

- [ ] Установить поддерживаемую JDK 17 и совместимые PostgreSQL/PostGIS; сверить версии с текущими Gradle и Flyway файлами, не брать исторический план за фактическую сборку.
- [ ] Изменить bootstrap: сейчас Flyway и runtime используют один `ServerConfig` и пул. Разделить учётные записи БД для миграций и обычной работы приложения, выдать минимальные права и ограничить сетевой доступ к PostgreSQL.
- [ ] Подготовить хранилище секретов или переменные окружения для `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`, `JWT_SECRET`, `SERVER_HOST`, `SERVER_PORT`, `JWT_TTL_SECONDS` и настроек публикации политики. Использовать новый сильный JWT secret; не переносить локальный `.env` в репозиторий или образ.
- [ ] Настроить TLS, HTTPS/WSS, сертификат, reverse proxy, firewall и прослушивание нужного интерфейса. Проверить, что backend и БД не открывают лишние порты.
- [ ] Настроить постоянный том БД и приватное объектное хранилище пользовательских файлов, резервные копии, срок хранения и пробное восстановление на изолированном контуре.
- [ ] Подготовить безопасный способ доставки сборки, отката версии приложения и запуска процесса после перезагрузки. Миграции Flyway применять последовательно, не переписывая уже применённые SQL файлы.

## Проверки перед открытием доступа

- [ ] Проверить `/health`, актуальную версию Flyway и подключение PostGIS на удалённой среде; записать commit/build ID, конфигурацию без секретов и результат.
- [ ] Проверить публичные auth-маршруты по HTTPS: опубликованный документ открывается без JWT; `GET /api/v1/legal/privacy` возвращает его действующие version/publishedAt/url; устаревшее согласие отклоняется; тестовый draft-режим выключен в переменных окружения и не доступен через reverse proxy.
- [ ] Проверить регистрацию, вход, `/me`, истечение JWT и logout текущего `jti` в тестовом контуре с обезличенными данными; повторный вход после отзыва и другие сеансы проверить отдельно.
- [ ] Проверить лимиты запросов на вход/регистрацию, ограничения тел и тайм-ауты, отсутствие паролей, JWT, телефонов и SQL-параметров в логах и мониторинге.
- [ ] Проверить доступность backend и документа политики с реальных Android/iOS клиентов, корректные API base URL, сетевые ошибки и защищённое хранение токена.
- [ ] Проверить работу резервного копирования и восстановления, мониторинг ошибок/диска/БД, процедуру ротации секретов и действия при недоступности сервиса.

## Как пополнять файл

Для нового требования добавьте пункт в подходящий раздел с конкретным действием и наблюдаемым результатом. Если требование появилось из задачи, укажите её ID и ссылку на документ backend. После выполнения замените `[ ]` на `[x]` и рядом запишите дату, окружение и краткое доказательство без секретов и персональных данных. Непроверенные пункты остаются открытыми.
