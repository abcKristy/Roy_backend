# Локальная приёмка B5.1–B5.3 до T133

Дата проверки — 07.11.2026. База интеграции — backend `c93ccd6`. Локальный кандидат содержит ранее принятые T115–T117 и T124–T126, три коммита T118–T120 и отдельные тематические коммиты остальных задач. Схема остаётся V016.

## Реализация

- **Группа 2, T118–T120.** Приватный порт Yandex Object Storage проверен через SDK на loopback. Локальный режим использует файловый адаптер. Замена ссылки в БД и постановка удаления атомарны. Чтение и ответ 304 требуют действующего сеанса и доступа владельца либо участника общего активного чата.
- **Группа 6, T127.** Локальная metadata и документ используют версию `draft-2026-11-01.2`. Устаревшее или отсутствующее согласие закрывает чтение центра и участие в подборе адресатов. В целевой среде обработка центра закрыта до подключения утверждённой политики.
- **Группа 3, T121–T123.** Смена пароля поддерживает действующие сессии V004 и отзывает прежние access и refresh. Удаление проверяет подтверждение и пароль, обезличивает общий контент, снимает личные связи и ставит очистку аватара. Воркер запускается штатным приложением и берёт задания по одному. Истёкший lease запрещает позднее подтверждение. Неуспешное удаление остаётся доступно для повтора оператором.
- **Группа 7, T128–T130.** API хранит один последний центр, отклоняет недопустимые координаты и отдаёт `Cache-Control: no-store`. PostGIS выбирает подходящих адресатов в пределах 1 км при создании предложения. Позднее сохранение центра не создаёт уведомления задним числом. REST и WebSocket получают публичный адрес и время начала, приватные ID чата и предложения скрыты. Push-only событие остаётся вне REST и WebSocket.
- **Группа 8, T131–T133.** Воркер проверяет актуальные настройки, согласие и привязку устройства перед отправкой. Claim и подтверждение ограничены lease, повторные попытки ограничены, сетевой вызов выполняется вне транзакции. Ответ по старому токену не отзывает заменившую его привязку. Адаптеры формируют `v=1`, а для nearby передают из целей только публичный `pointId`. [RuStore API](https://www.rustore.ru/help/sdk/push-notifications/send-push-notifications) · [APNs API](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns).

## Ревью

В независимом ревью проверены совместимость со старыми сеансами, транзакции удаления, безопасность аватаров и координат, очереди и форматы провайдеров. По замечаниям сохранены неуспешные задачи удаления, исправлен порядок блокировок при отзыве push-токена, неоднозначные ответы APNs больше не отзывают привязку, добавлены версия push payload и запрет кэширования центра карты.

Повторное независимое ревью подтвердило исправления. В общем прогоне дополнительно обнаружилась WebSocket-фикстура, которая сравнивала идентификаторы сеансов с разными сроками действия JWT. В тесте срок теперь совпадает с выданным токеном.

## Проверки

Локальный контур — JDK 17, Gradle 9.5.1, PostgreSQL 18.6, PostGIS 3.6.4. Для прогонов использовались новые изолированные базы на loopback с синтетическими данными. Flyway применил и сверил V001–V016. Сборка `installDist` прошла.

- **42 целевых теста** без БД прошли без ошибок и пропусков. В наборе конфигурация, локальное хранилище, SDK-адаптер Yandex, загрузка, черновая политика, шифрование токена, RuStore/APNs и маршруты документации.
- **69 интеграционных сценариев** прошли на PostGIS без ошибок и пропусков. В проверку вошли замена и чтение аватара, профиль и удаление аккаунта, смена пароля, настройки, привязка и шифрование токена, центр карты, события и воркеры. Повторный прогон набора воркеров на чистой БД подтвердил 10 из 10 после изоляции синтетических push-событий от проверки in-app рассылки.
- **Штатный запуск** на loopback вернул `200` на `/health` и версию черновой политики. Запущенный приложением воркер удалил файл из приватной локальной папки и зафиксировал `DONE` в БД.

OpenAPI сверил 48 операций с Ktor и проверил 456 примеров. Коллекция Postman прошла проверку по схеме v2.1. Изменение коллекции добавляет три операции аватаров.

Общий `check` без БД завершился с одним сбоем из 335 тестов и 226 пропусками. `MeetingAcceptanceFixtureIntegrationTest` ожидал ошибку из сценария M4, но завершился раньше из-за отсутствия `TEST_DATABASE_URL`. Тот же сбой воспроизведён на исходном `c93ccd6`. Отдельный прогон B5 с обязательной PostGIS завершился без пропусков. В финальном общем прогоне проверка WebSocket прошла.

## Этапы 4–5

При переносе остаются подключение приватного бакета и KMS, публикация утверждённой политики, подключение эксплуатационного ключа и учётных данных push. Приёмка целевой среды включает проверку закрытого доступа и шифрования в бакете, production-согласия по HTTPS и фактических отправок RuStore/APNs на устройства.
