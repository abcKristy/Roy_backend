# M1.T2 registration implementation

`POST /api/v1/auth/register` accepts the v1 request and returns the full `Session` shape when a published privacy policy provider is available. The service validates E.164 phone, trimmed display name (1–80 Unicode code points), password (8–128 Unicode code points), age at least 12, and the exact current privacy version. A stale or empty version returns `422 PRIVACY_POLICY_ACCEPTANCE_REQUIRED` with `details.currentVersion`; an absent required JSON field is rejected by the transport as `422 INVALID_FIELD`. The database unique index maps a duplicate phone race to `409 DUPLICATE_PHONE`.

The JDBC repository inserts `users`, `auth_sessions`, and `notification_settings` on one connection and commits them together. Defaults for the notification row are `true,true,false,false`, revision 0. The access JWT is signed from `JWT_SECRET` and contains `sub`, `jti`, `authVersion=0`, `iat`, and `exp`. Its default lifetime is 15 minutes (`JWT_TTL_SECONDS`). Registration also returns a rotating refresh token for the fixed session lifetime, default 30 days (`REFRESH_TTL_SECONDS`); only its hash is persisted. Server time comes from an injectable UTC clock.

The composition root uses the local draft in `docs/privacy-policy-draft.md` only when `APP_ENV=local`, `AUTH_DRAFT_POLICY_ENABLED=true`, `SERVER_HOST` is loopback and `PUBLIC_BASE_URL` is a loopback origin. Otherwise the route returns `503 SERVICE_UNAVAILABLE` before hashing or any database write. The draft is intended for local test accounts only. Public registration requires an approved policy with operator details and a stable HTTPS document URL.

Privacy publication is an immutable snapshot within this server process. In the current local single-process setup, it cannot switch versions between validation and commit. A future multi-instance rollout must drain all old instances or validate the active version under a shared database lock; process immutability alone cannot enforce a global version transition. Password hashing runs on `Dispatchers.Default` behind a shared two-slot semaphore, bounding the Argon2id memory used by registration to about 38 MiB at the provisional local cost. Login uses this same work coordinator. Sensitive DTO `toString` methods redact credentials and personal values.
