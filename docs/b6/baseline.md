## Локальный контур

- Windows, JDK Oracle HotSpot 17.0.10+11-LTS-240, Gradle Wrapper 9.5.1, Kotlin 2.4.20, Ktor Netty 3.6.1, Flyway 13.11.1 и PostgreSQL JDBC 42.7.14.
- Изолированная PostgreSQL 18.6/PostGIS 3.6.4 из локального образа `postgis/postgis:18-3.6`. Backend и проброшенный порт БД привязаны к loopback. Сервер, фоновые задачи и WebSocket запускаются в одном процессе. [Правила изоляции и обязательный прогон](../integration-test-safety.md).
- `APP_ENV=local`. Локальная правовая фикстура включается `AUTH_DRAFT_POLICY_ENABLED=true` и loopback `PUBLIC_BASE_URL`. Использовать синтетические аккаунты. Для проверок нужны отдельные `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`, `JWT_SECRET` и, по способу применения миграций, `MIGRATION_DATABASE_USER` и `MIGRATION_DATABASE_PASSWORD`. Значения выдаются одноразово в окружение запуска. [Настройка сервера](../../README.md).
- Локальный файловый аватар, ручной адрес или контролируемый ответ геокодера, контролируемые ответы push. Внешние сервисы и production-ключи отсутствуют в локальной конфигурации. Локальный HTTP обслуживает только loopback. Проверка HTTPS/TLS для целевой среды относится к этапам 4–5.

## Реестр результатов и ограничений

- **Исторический PASS B5.4–B5.5.** По [протоколу T145](../m5-b54-b55-local-handoff.md) `check installDist` завершился успешно, 110 выполненных тестов из 346 и 236 штатных пропусков без БД. Обязательный PostGIS-прогон — 67 выполненных сценариев без ошибок и пропусков. OpenAPI — 48 операций и 456 валидных примеров. Эти результаты относятся к кандидату T145.
- **Исторический PASS B5.1–B5.3.** [Протокол](../m5-local-acceptance.md) содержит свои сборку, условия и отдельные результаты. Прежний сбой тестовой фикстуры M4 без БД закрыт в T143, что подтверждено T145.
- **NOT_RUN B6.** Новая функциональная, конкурентная, нагрузочная и целевая приёмка не выполнена этим паспортом. Пороги производительности и формальное решение BG-1 проверяются последующими задачами. На этапе 2–3 понадобятся отдельные Android/iOS результаты.
- **BLOCKED до внешней конфигурации этапов 4–5.** Публичная утверждённая политика, приватный бакет и KMS, эксплуатационный ключ, внешние карта/геокодер, реальные RuStore/APNs и целевые HTTPS/TLS и восстановление. Локальные fixture-ответы покрывают только внутренний контракт. [Реестр подготовки целевой среды](../remote-server-readiness.md).
- `knownDefects` — T145 перечисляет исправленные stale nearby, голодание ограниченной выборки и доставку по закрытому предложению. Новые отклонения B6 записывать с требованием, case ID, версией и воспроизведением. Отсутствие зарегистрированного отклонения не заменяет результат проверки.

T147 использует этот паспорт как версионированный вход. Версии клиента в локальном серверном паспорте неприменимы.
