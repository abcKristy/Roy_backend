# T171 · Удаление аккаунта и сроки хранения

Аудит backend выполнен на этапе 1, 7 ноября 2026 года. Исполнитель — Codex, локальный контур. Аудит использует синтетические данные и исторические результаты на `0a2ac7186e325dc095c77b50890c7fc385437c49` с PostgreSQL 18.6, PostGIS 3.6.4 и схемой V016. В `build/b6-evidence/initial.json` (SHA-256 `0e6708c83f1c03393d4938b9f98c8a8064099e867cbf42b3ec43093f5db9f3b6`) все четыре перечисленных класса удаления и `JobsIntegrationTest` имеют PASS без пропусков. Результат относится к этим классам.

| Проверка | Наблюдение | Свидетельство |
| --- | --- | --- |
| ERASE-01 · Доступ и подтверждение | Обязательны верный текущий пароль и `confirm=true`. Ошибка пароля и отсутствие подтверждения отклоняются. Успех даёт HTTP 204, прежний access-токен получает 401. | `AccountDeletionRoutesIntegrationTest`, API-028 в [каталоге API](api-cases.md). |
| ERASE-02 · Аккаунт и личные данные | Отзываются активные сессии. Удаляются регистрации устройств, центр карты, настройки уведомлений, личная история и служебные записи пользователя. Строка аккаунта теряет телефон, хеш пароля, имя, возраст и аватар. Гонка с созданием уведомления завершается удалением этого уведомления. | `AccountDeletionPrivateCleanupIntegrationTest`, `AccountDeletionFanoutConcurrencyIntegrationTest`. |
| ERASE-03 · Общие данные | Удаляются членства и голоса, пересчитываются результаты предложений. Точки, оставшиеся без участников, удаляются. Сохранившийся общий текст отделяется от прежнего автора и выдаётся без старого имени и аватара. Запись жалобы может сохраняться со ссылкой на обезличенную строку аккаунта. | `AccountDeletionServiceIntegrationTest`, `AccountDeletionPrivateCleanupIntegrationTest`. |
| ERASE-04 · Медиа | Удаление строки-ссылки и постановка ключа в очередь входят в транзакцию удаления аккаунта. Успешная или уже выполненная очистка завершает задачу, сбой допускает повтор. Незавершённая задача остаётся доступной для обработки. | `AccountDeletionServiceIntegrationTest`, `JobsIntegrationTest`, [локальная проверка медиа](t170-private-media-audit.md). |

`deleteEvidence` для локального контура включает HTTP 204 и последующий 401, состояния строк личных данных и обезличенного общего графа, очередь удаления медиа и переходы worker. HTTP 204 подтверждает логическое удаление из работающей системы. Физическое удаление объекта подтверждает отдельный результат worker.

Локальный `RetentionCleanup` удаляет истёкшие сессии и события лимитов сообщений старше суток. Записи идемпотентности и завершённые push jobs очищаются через 30 дней по своим временным отметкам. Для media jobs правило 30 дней применяется только к `DONE`. Незавершённые удаления сохраняются для повторной обработки. Общая история сообщений, жалобы и история уведомлений не удаляются этим worker по возрасту. Удаление аккаунта отдельно удаляет личную историю.

`backupRetention` фиксируется в локальном плане как требование к целевому контуру. Локальные disposable базы создаются из синтетических данных и уничтожаются по окончании прогона. На этапе 4 нужно задать срок хранения и порядок доступа к резервным копиям БД и объектов, а на этапе 5 записать фактические настройки, проверку восстановления и истечения хранения. Подтверждение логического удаления из действующей БД и подтверждение истечения резервных копий ведутся отдельно. [План серверной готовности](../remote-server-readiness.md).
