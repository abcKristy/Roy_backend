# T168. Локальная проверка прав на ресурсы

Дата — 07.11.2026. Исполнитель — Codex. Backend принят для проверки от `0a2ac71`, схема V016. Трассировка всех операций находится в [матрице T142](../mvp-backend-coverage.md). Сверены OpenAPI, регистрация маршрутов и привязка actor в обработчиках. Клиентский артефакт для этого серверного шага не требуется.

## Граница доступа

- Публичный набор из 10 операций включает 7 GET из матрицы и POST регистрации, входа и refresh. Refresh требует refresh token в теле, публичные privacy metadata и документ доступны при разрешённой конфигурации. Swagger обслуживается отдельными публичными маршрутами.
- В полном контракте OpenAPI остальные 38 REST-операций защищены действующей bearer-сессией. При настроенном шифровании токенов устройств обе операции с установкой доступны. Без ключа PUT проверяет bearer и для действующей сессии с корректным ID возвращает `503 PUSH_REGISTRATION_FAILED`. DELETE в этой конфигурации не зарегистрирован и возвращает 404.
- В read-маршрутах карты доступна публичная проекция. Запись точки, добавление темы и вступление используют actor сервера. Добавление темы и вступление в публичную тему не требуют уже существующего членства, так как сами создают его.
- Чат, история, поиск, read cursor, сообщения и предложения используют активное членство в целевом чате. Бронь требует собственного голоса и актуальной ревизии. Закрытие требует автора предложения.
- Профиль, настройки, установка и позиция привязаны к аккаунту токена. Чужой ID уведомления не даёт доступа к событию или отметке read. Аватар доступен владельцу и участнику общего активного чата, в том числе при повторной условной загрузке.
- WebSocket проверяет bearer на upgrade и повторно проверяет сессию и членство при подписке и отправке scoped событий. Уход снимает доступ к событиям темы. Отзыв текущей сессии закрывает её socket с 4401.

## Исполняемые проверки

- `MvpBackendChainIntegrationTest` проверяет гостевую карту, отказ записи без входа, 403 неучастнику, события WS для участника, публичную nearby-проекцию и 404 на чужой read.
- В `WebSocketSubscriptionIntegrationTest` Ktor `testApplication` с реальной БД проверяет чужой чат при subscribe, снятие прав после leave и независимый отзыв одной из двух сессий. Отдельный нативный Netty-блок проверяет REST-авторизацию и отказ WebSocket upgrade при недействующей сессии.
- `PushTokenEncryptionIntegrationTest` проверяет ответы PUT и DELETE без ключа. [Протокол T126](../m5-t126-push-token-encryption.md).
- `HistoryAccessIntegrationTest`, `MeetingRoutesIntegrationTest`, `AvatarReadRoutesIntegrationTest`, `NotificationHistoryIntegrationTest` и `NotificationRoutesIntegrationTest` проверяют права на соответствующие типы ресурсов. Матрица связывает остальные варианты с отдельными тестами.

Проверка исходников охватывает весь список. Результаты исполняемых проверок относятся только к запущенным сценариям и их фикстурам. Фактическая доступность закрытого бакета вне API проверяется на этапе 5.

Локальный `tools/api_docs.py check` подтвердил точное соответствие 48 операций Ktor и 456 валидных примеров. Проверки авторизации и ACL WebSocket этой ветки выполнены на одноразовой `roy_m3_chat`. Сквозное HTTP/WS/JDBC свидетельство для остальных указанных групп приведено в [пакете T145](../m5-b54-b55-local-handoff.md). Итоговый расширенный прогон учитывается отдельно по его фактическим результатам.
